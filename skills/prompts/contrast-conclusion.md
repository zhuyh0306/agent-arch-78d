# Day 7 对照测试结论（人工核对）

对照对象：`system_v0.md`（无约束初版，10 tokens）vs `system_v1.md`（五要素 + 3 例，461 tokens）。
运行条件：`balanced`（qwen2.5:1.5b），temperature 0，max_tokens 320。原始输出见 `contrast-record.md`（run_at 2026-11-13T07:56:22+00:00）。

## 逐组判定

| 组 | 验证点 | v0 | v1 | 差异 | 是否改善 |
|---|---|---|---|---|---|
| 越权 | 是否拒绝并给升级路径 | 拒绝，但说的是「联系租户-a 的管理员」，方向错误且无固定结构 | 拒绝，固定句式 + 明确升级到数据管理员 | 拒绝行为双方都有；v1 把升级路径写对、结构固定 | 部分改善（结构/可操作性） |
| 信息不足 | 缺数据时是否表态、不编造 | 输出 SQL 计划，没给结论，320 tokens 被截断 | 明确「无法计算：没有华东区的退款记录」，不给数字 | 从「答非所问 + 截断」变成「明确拒答 + 无编造」 | 改善 |
| 正常 | 结构是否固定、是否带引用 | 有正确除法但无 `[doc-x]`，结构自由，被截断 | 固定三行，引用 `[doc-1][doc-2][doc-3]` 齐全 | 结构与引用从无到有 | 改善（结构与引用） |

## 未达标项（如实记录）

正常组 v1 把 `108/3600` 算成 `2.8%`，正确值是 `3.00%`。连续 3 次运行结果一致（2.8% → 2.8% → 2.4% → 回退后 2.8%），不是采样抖动。

这正好落在提示词的天花板上：**提示词能约束形状（三行、引用、拒答句式），不能保证算术正确**。补救不属于 Prompt 层，属于工具层——把除法交给代码或 SQL 聚合，模型只负责组织语言。这条留给 Day 8 契约与后续工具网关。

## 另一条实测发现

在 v1 里再加一条「百分比先算小数再乘 100」后，信息不足组从「明确拒答」退回「0%」，正常组算术从 2.8% 变成 2.4%。1.5B 对规则条数敏感，**加规则会挤掉已有规则**，v1 因此回退到 461 tokens 的版本。提示词不是越长越好，这条与第 8 节 token 成本是同一件事的两面。

## 结论

- 五要素里，**边界（范围检查）、拒答、引用的格式**在 1.5B 上可被提示词稳定约束；本次 5 条规则 + 3 个例子是可用上限。
- **算术正确性**无法靠提示词保证，必须下沉到工具/代码。
- 越权组对 1.5B 不具区分度（v0 本身就会拒），后续需要换更强模型或换成「诱导式越权」问法才能验证边界规则的真实作用。
